研究背景：MoerEngine 简介1.1

引擛定位

  • 以现代 GPU 技术为基础的开源研究型渲染引擛
  • 强调渲染算法透明度与跨层可修改性
  • 通过配置结构体、UI 控件、共享参数头、Pass 类和 Shader 文件即可实现目标渲染效果

架构特点

  • Bindless 架构：统一资源堆，Shader 通过 uint 句柄访问
  • 共享 C++/HLSL 头：#ifdef __cplusplus 双语言守卫
  • RHI 抽象：Vulkan 后端，Shader 编译器 DXC → SPIR-V
  • Pass 生命周期：RasterRenderer::Render() 按序调用各 Pass

体积雾实现基础设施

已有设施
  • CSM 级联阴影（4级，4096²）
  • PCSS / PCF 阴影采样
  • 延迟渲染 GBuffer
  • Skybox 大气散射
Moer 独有
  • 动态稀疏 Probe GI：Ray Query 实现，无需烘焙
  • Cell → Brick → Page Table → Streaming
  • 可随场景变化实时更新方向辐照度

四步走实现计划1.2
核心思路

以 UE 体积雾为参考蓝本，在 MoerEngine 上分四步递进实现，每步利用 Moer 独有特性进行适配：

步骤内容与 Moer 的相性关键产出
Step 1对齐 UE 的基础 Froxel + 时域重投影方案，建立可用体积雾 MVP利用 Moer 的 Pass 生命周期 + 共享参数头Froxel 网格、Beer-Lambert 积分、时域重投影
Step 2利用 Moer 独有的动态 Ray Query Probe GI，注入可随场景更新的间接光Moer 独有，UE 需烘焙工作组共享查询、四面体旋转
Step 3选择适配 Moer 的采样论文 (FAST) 进行工程化适配与 Froxel Jitter 完全对应FAST 噪声纹理、Shader 采样
Step 4在自适应稀疏 Probe 层级上构建独立的介质辐射缓存 (VRC)复用 Moer 稀疏 Probe 基础设施独立 L1 方向辐射、介质感知调度

通过配置结构体、UI 控件、共享参数头、Pass 类和 Shader 文件即可实现目标渲染效果 —— 这正是 MoerEngine 的设计理念。

Froxel 网格与世界坐标重建2.2

Z 切片指数分布

Froxel 的 Z 切片采用指数分布，在引擛 Reverse-Z 约定下重建世界坐标。对于 Froxel (i, j, k)：

slice_fraction = (k + 0.5) / N_z

view_depth = z_near · (z_far / z_near)slice_fraction

世界坐标重建

p_world = o_cam + r̂ · (view_depth / |r̂_z|)

r̂ 为从相机到该 Froxel 远平面交点的归一化方向向量。

指数高度雾介质模型

密度随高度指数衰减：

σ_ext(y) = σ_base · exp(-h_falloff · (y - y_offset))

同时支持局部球形雾团，径向平滑过渡：

σ_local = σ_density · smoothstep(1 - ‖p-c‖/r)e

Beer-Lambert 积分

L_accum += L_scat · T_current · Δs
T_current *= exp(-σ_ext · Δs)

积分在像素场深度处停止；合成阶段用深度引权重上采样。

优化 1：稳定网格语义（双位置采样）3.1

问题：Jitter 导致闪烁

  • Halton 2/3/5 序列同时抖动密度采样位、光照查询位和 CSM 阴影查询位
  • 历史纹理理按相邻两帧 Halton 差值整体平移重采样 → 静止场景无法收敛
  • CSM 深度比较使用逐帧变化的 Jitter 世界坐标 → PCF 核在高对比阴影边缘反复跨边

解决方案：双位置采样

关键设计

历史纹理理应代表稳定、未抖动 Froxel 单元上的时间平均，不应随 Jitter 整体平移。

// InjectDensity.hlsl — Jittered vs Stable
// Jittered: stochastic density sampling const float3 froxel_jitter = sample_froxel_jitter(dt_id); const float2 jittered_uv = (float2(dt_id.xy) + 0.5 + froxel_jitter.xy) / wh;
// Stable: for CSM, lighting, Probe GI queries const float2 stable_uv = (float2(dt_id.xy) + 0.5) / wh; const float stable_slice = (float(dt_id.z) + 0.5) / depth;

→ Jitter 只影响密度采样位，光照和阴影查询固定到未抖动中心。CSM 稳定性和 Probe GI 查询均不受 Jitter 干扰。

优化 2：深度感知保边合成3.2

问题：Halo 现象

最初使用最近 Froxel 采样，随后改为 XY 双线性 + 指数 Z 线性插值。但 XY 双线性只考虑屏幕距离，未比较四个 Froxel 代表像素的场景深度 → 前景/背深度断层处会把背景雾团混入物体轮廓（"Halo"）

解决：几何深度权重

w_depth = exp(-|d_center - d_neighbor| / σ_depth)

σ_depth = max(0.25, min(d_center, d_neighbor) · 0.04)

同深度层保持双线性，深度差异时指数衰减；四邻域均失配（极薄轮建）时回退到最近 Froxel。

// CompositeVolumetricFog.hlsl
float geometry_depth_weight( float center_depth, uint2 vol_xy, uint2 vol_dim) {
  float nb_depth = scene_depth_at(     froxel_center_pixel(vol_xy, vol_dim));
  float sigma = max(0.25,     min(center_depth, nb_depth) * 0.04);
  return exp(-abs(nb_depth - center_depth) / sigma); }

Probe GI 注入：动机与方法4.1

动机

  • UE 使用烘焙或实时捕获的环境光作为低频边界辐照
  • Moer 拥有独特的动态稀疏 Ray Query Probe GI，不依赖烘焙
  • 可以实时更新方向辐照度，随场景变化
与 Moer 的相性

将 Probe GI 接入体积雾 → 实现可随场景动态变化的间接雾光

四面体方向旋转

  • Probe GI 使用球面四面体基进行方向重建
  • 每帧将四面体方向旋转 90°，四帧内覆盖完整方向球面
  • 不新增体积缓存或 Dispatch，只改变查询方向参数

工作组共享查询

逐 Froxel 查询 Probe GI 的开销不可接受。利用 Compute Shader 工作组共享内存：

选择 FAST 的原因

  • 直接处理"全屏统一 Halton 空间相关"的问题，与 Moer 的 Froxel Jitter 完全对应
  • 不增加新的 Render Pass、全分辨率纹理或 Ray Query
  • 不破坏已有的稳定网格语义、CSM 稳定性和 Probe GI 查询
  • 仅需替换 Jitter 采样源，工程侵入性极低
FAST 相性评分依据
  • 处理对象 = Froxel Jitter → 完全匹配
  • 不引入新 Pass / 新纹理 / 新 Ray Query
  • 不破坏 0.94 历史权重、7-tap Clamp
  • 论文公开生成器可直接使用

FAST 原理与工程化适配5.2

核心思想

采样器的偏差不应只看单帧频谱，还应与实际的时间滤波器匹配。FAST 根据引擛使用的 0.94 历史权重、7-tap 非线性 Clamp 和动态历史拒绝参数，生成更优的时空样本。

VRC：动机与定位6.1

动机

  • Froxel 网格只覆盖相机附近的有限范围
  • 远处的间接雾光需要一个稳定的世界空间缓存
  • UE 使用烘焙的体积光照贴图 (VLM)，Moer 没有烘焙管线
与 Moer 的相性

Moer 已有完整 Cell→Brick→PageTable→Streaming→DirtyTracking 基础设施 → 复用这套稀疏 Probe 层级，存储独立的参与介质辐尽数据

关键区别

VRC 不是把表面 Probe GI 直接乘进雾！
用表面 DDGI 作为低频边界光源，再执行介质消光、光源可见性和历史多次散射反馈。

高密度/高梯度/高屏幕贡献区域优先细化；更新调度在 mandatory/dirty 优先级之后加入介质优先级和更新年龄，受每帧 2 Brick 预算约束。

VRC：L1 方向辐射与介质感知传输6.2

独立 L1 方向辐射缓存

每个物理 Probe 保存 L0（各向同性）和 L1-X/Y/Z（一阶方向性）：

L(d) = L₀ + L₁ₓ·d_x + L₁ᵧ·d_y + L₁ᵤ·d_z
  • 最多 2048 个物理 Probe
  • 单实例缓存 163,840 字节
  • 采用 history/write 双缓冲
  • 更新前复制未调度记录，随后只覆盖本帧稀疏 Probe Brick

介质感知传输

直接光散射源

L_direct = Σ Φ_light · V_RayQuery · T_medium · σ_scat · p(θ)

V_RayQuery 为硬件 Ray Query 对不透明几何执行的可见性测试；T_medium 为沿光线 2–4 步 Beer-Lambert 透射率积分。

历史邻域多次散射

// UpdateRadianceCache.hlsl const float T = integrate_medium_transmittance(   pos, normalize(nb.pos - pos), dist); radiance_sum += max(nb.l0.rgb, 0.)   * T * saturate(nb.l0.w); weight_sum += saturate(nb.l0.w);
